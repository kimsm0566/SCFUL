# 프로젝트 진행 흐름과 현재 결론

## 1. 이 프로젝트가 답하려는 질문

이 프로젝트의 대상은 분류기가 아니라, 다음과 같은 **재구성 기반 의미 통신 codec**이다.

```text
입력 이미지 x -> encoder -> 물리 채널 -> decoder -> 복원 이미지 x_hat
```

연합학습으로 codec을 학습한 뒤 특정 client가 삭제를 요청했을 때, 목표는 target
client의 이미지를 단순히 나쁘게 복원하게 만드는 것이 아니다. 올바른 목표는 다음과
같다.

```text
삭제 후 codec ~= 처음부터 target client 없이 연합학습한 codec
```

따라서 모든 실험에서 비교 기준은 다음 세 모델이다.

| 표기 | 의미 |
| --- | --- |
| `origin` | 모든 client 데이터를 사용해 학습한 원본 FL codec |
| `retrain` | target client를 제외하고 처음부터 다시 FL한 기준 codec |
| `SCU` | 원본 codec에서 target client를 삭제하도록 조정한 codec |

이 문서에서는 `retrain`을 “정답 모델”이나 “oracle”이라고 부르지 않고, **client 0
제외 재학습 기준 model**이라고 부른다. 실제 삭제 후 model이 이 기준 model과 얼마나
가까운지가 핵심이다.

## 2. 진행 흐름

### 2.1 평가 기준을 바로잡음

초기에는 target 데이터의 reconstruction MSE가 커지면 잘 삭제된 것으로 해석하기
쉽다. 그러나 이는 잘못된 기준일 수 있다. target client가 빠져도 다른 client가 같은
semantic을 충분히 갖고 있으면, `retrain` model 역시 target 입력을 잘 복원할 수 있기
때문이다.

그래서 이후 실험의 주 지표를 다음으로 정했다.

```text
output gap = mean((x_hat_비교모델 - x_hat_retrain)^2)
```

이 값이 작을수록 비교 model의 실제 복원 동작이 `retrain`과 가깝다. target 입력과의
MSE는 삭제 성공의 단독 근거가 아니라 보조 진단으로만 사용한다. 상세 기준은
[전체 실험 계획](08-14-01-전체-실험-계획.md)에 정리되어 있다.

### 2.2 통제된 중앙집중 실험으로 shared/target-specific 가설을 점검함

MNIST와 CIFAR-10의 통제된 분할에서 다음을 먼저 확인했다.

- target client만 갖는 것처럼 보이는 이미지도, 남은 데이터로 학습한 `retrain` model이
  일반화로 어느 정도 복원할 수 있다.
- 따라서 “target-specific이면 반드시 복원이 깨져야 한다”는 식의 이분법은 성립하지
  않는다.
- `forget-only`처럼 target loss만 크게 만드는 조정은 target뿐 아니라 retained utility도
  심하게 훼손할 수 있다.
- client semantic distribution을 latent의 단일 Gaussian `N(mu_k, sigma_k^2)` 하나로
  표현하는 것은 초기 진단에는 쓸 수 있어도, 다중 class 분포와 지원량 차이를 충분히
  설명하지 못했다.

이 결과로 shared와 target-specific을 고정된 두 부류가 아니라, **삭제 후 남는 semantic
support의 연속적인 정도**로 다루기로 했다.

### 2.3 단일 client 삭제에서 10-client FL 삭제로 확장함

이후 CIFAR-10 semantic codec과 FL 실행 경로를 정비했고, 실제 FL 조건으로 비교를
확장했다.

- client 수: 10명
- 각 client 데이터 수: 동일하게 5,000개
- 삭제 대상: client 0
- channel: codec 학습·평가에 AWGN 경로를 포함
- 기준 학습: `origin` 200 rounds, `retrain` 200 rounds

두 data setting을 사용했다.

| 설정 | 목적 |
| --- | --- |
| FedOSD와 같은 2-class/client pathological split | 매우 강한 label non-IID에서 SCU의 retained-data compensation을 확인 |
| Dirichlet `alpha=0.1`, equal-size split | client별 class 비율은 불균형이지만 총 데이터 수는 동일한 실제적인 FL 삭제 상황을 확인 |

실행 설정, split manifest, checkpoint, class별 결과는 각 run 출력 폴더에 남기도록
구현했다.

### 2.4 `forget-only`를 유효한 SCU 비교로 쓰지 않기로 결정함

`forget-only`는 full SCU가 아니라 target 쪽 손실만 사용하는 축소 변형이다. 초기에는
파괴 정도를 보는 진단으로 실행했지만, SCU 자체의 성능을 대표하지 않고 retained
utility를 의도적으로 망가뜨릴 수 있다.

따라서 다음 원칙을 확정했다.

- 앞으로 `forget-only`는 주 실험이나 제안 방법의 비교 대상으로 실행하지 않는다.
- 과거 `forget-only` 결과는 왜 target MSE만으로 삭제를 판단하면 안 되는지 보여 주는
  **무효인 역사적 진단 기록**으로만 남긴다.
- SCU 비교는 target forgetting과 retained-data compensation을 함께 쓰는 **full SCU**로
  한다.

관련 무효 기록은 [08-17-01](08-17-01-fedosd-호환-scu-세모델-실험.md) 및
[08-17-02](08-17-02-fedosd-호환-scu-seed0-결과.md)에 명시되어 있다.

### 2.5 centralized full SCU의 역할을 분리해 확인함

full SCU에서는 서버가 남은 client 데이터 전체 `D_r`를 모아 compensation loss에
사용한다. 이는 우리가 최종적으로 허용할 설정은 아니다. 최종 방법은 남은 client의
raw data를 중앙에 모으지 않아야 한다. 다만 이 실험은 다음 질문을 분리하는 데 필요하다.

> SCU가 retained raw data를 직접 볼 수 있다면, compensation 자체는 codec 손상을
> 막는 데 도움이 되는가?

FedOSD형 2-class/client 분할에서 full SCU는 `forget-only`에서 보였던 큰 붕괴를
피하고 reconstruction quality를 유지했다. 즉 **남은 data를 이용한 compensation의
역할 자체는 의미가 있다.** 그러나 full SCU가 항상 `retrain`에 더 가까워졌다는 결과는
아니다. 이 점이 이후의 분산 repair 문제를 구체화한다.

### 2.6 Dirichlet alpha=0.1에서 class support 감소를 직접 측정함

사용자가 제기한 핵심 질문은 다음이었다.

> Dirichlet `alpha=0.1`이면 어떤 class가 client 0에 많이 몰릴 수 있다. client 0을
> 지우면 그 class의 절대 수와 전체 대비 비율이 크게 줄어드는데, 그래도 삭제 전후 model
> behavior가 차이 없다고 할 수 있는가?

이 질문을 확인하기 위해 class별 삭제 비율을 다음처럼 정의했다.

```text
rho(class c) = client 0의 class c 개수 / 전체 class c 개수
```

`rho`가 클수록 client 0 삭제 뒤 남는 class support가 작다. `rho`에 따라
shared-high, medium, low-support, strict target-specific을 나누되, 분석 자체는 연속값
`rho`를 보존한다. 이 분석의 구현과 결과는
[08-18-01 Dirichlet support 반응 분석](08-18-01-dirichlet-support-반응-분석.md)에 있다.

## 3. 현재 유효 결과

### 3.1 FedOSD형 pathological split의 centralized full SCU

이 조건에서는 client 0과 client 1이 같은 label 0, 1을 보유한다. 즉 삭제 대상의
semantic은 남은 client에도 직접 존재하는 강한 shared 조건이다.

| model | 전체 reconstruction MSE | `retrain`과의 output gap |
| --- | ---: | ---: |
| `origin` | 0.015428 | 0.000260 |
| `retrain` | 0.015418 | 0.000000 |
| centralized full `SCU` | 0.014737 | 0.000738 |

full SCU의 MSE가 나쁘지 않다는 것은 compensation이 model을 무너뜨리지 않았다는
뜻이다. 반면 output gap이 원본보다 작아지지 않았으므로, 이 한 조건에서 full SCU가
`retrain` equivalence를 개선했다고 주장할 수는 없다. 상세 수치와 조건은
[08-17-04 중앙집중 full SCU 결과](08-17-04-중앙집중-full-scu-seed0-결과.md)에 있다.

### 3.2 Dirichlet alpha=0.1: `origin`과 `retrain`의 class별 변화

5개 seed, 200 rounds의 `origin`/`retrain` 전용 실행을 모아 class별 output gap을
분석했다. client 0에 class sample이 500개 이상 있었던 10개 class-seed 조합에서는
다음과 같았다.

| 삭제 support 구간 | 관측 수 | `origin`의 평균 output gap |
| --- | ---: | ---: |
| shared-high (`rho <= 0.2`) | 2 | 0.000234 |
| medium | 6 | 0.000246 |
| low-support (`rho >= 0.6`) | 2 | 0.000275 |

low-support에서 평균이 조금 큰 방향은 사용자의 직관과 맞지만, 관측 수가 적고 절대
차이도 매우 작다. eligible 10점에서 `rho`와 output gap의 Pearson 상관은 0.164,
순위 상관은 0.067이었다. 따라서 현재 조건에서는

```text
삭제 비율이 높을수록 output gap이 확실히 커진다
```

라고 결론낼 근거가 없다. 그렇다고 support가 중요하지 않다는 뜻도 아니다. 5 seeds와
현재 codec/학습 길이에서 **측정 가능한 단조 관계를 아직 보지 못했다**는 의미다.

예를 들어 seed 3에서는 label 1의 `rho=0.7312`로, 5,000개 중 3,656개가 client 0에
있었다. 삭제 후 이 label은 1,344개만 남았다. 반대로 label 7은 `rho=0.1792`로 4,104개가
남았다. 이처럼 delete 후 class support 차이는 실제로 크게 발생한다. 그런데 이 차이가
codec의 output 변화로 얼마나 이어지는지는 추가 검증이 필요하다.

### 3.3 같은 Dirichlet split에서 centralized full SCU

가장 강한 support 대비를 보인 seed 3에서 full SCU도 실행했다.

| 대상 | model | reconstruction MSE | `retrain`과의 output gap |
| --- | --- | ---: | ---: |
| 전체 | `origin` | 0.015154 | 0.000193 |
| 전체 | `retrain` | 0.015479 | 0.000000 |
| 전체 | centralized full `SCU` | 0.014845 | 0.000551 |
| label 1, low-support | `origin` | 0.019825 | 0.000224 |
| label 1, low-support | centralized full `SCU` | 0.019540 | 0.000611 |
| label 7, shared-high | `origin` | 0.017070 | 0.000209 |
| label 7, shared-high | centralized full `SCU` | 0.016651 | 0.000548 |

이 run에서도 SCU는 reconstruction quality를 크게 잃지 않았다. 하지만 low-support
label 1과 shared-high label 7 모두에서 `retrain`에 더 가까워지는 선택적 효과는 확인되지
않았다. 특히 수치가 작으므로 2배 같은 비율 표현으로 효과를 과장하지 않는다. 이 결과는
[08-18-02 Dirichlet full SCU support 분석](08-18-02-dirichlet-full-scu-support-분석.md)에
정리되어 있다.

## 4. 현재 결론

### 확인된 점

1. 삭제 성능의 기준은 target MSE 증가가 아니라 `retrain`과의 functional gap이다.
2. retained data를 함께 쓰는 full SCU는 target-only forgetting과 달리 reconstruction
   utility의 큰 붕괴를 피할 수 있다.
3. Dirichlet non-IID에서 client 삭제는 class별 support를 실제로 크게 바꿀 수 있다.
   따라서 global 평균만으로 삭제 영향을 판단하면 안 된다.
4. shared/target-specific은 이분법이 아니라 삭제 후 남는 support의 정도로 측정해야 한다.

### 아직 확인되지 않은 점

1. 현재 5-seed Dirichlet 결과만으로 support 감소가 `origin`과 `retrain` 사이 output
   gap을 단조롭게 키운다고 말할 수 없다.
2. full SCU가 현재 조건에서 `retrain` equivalence를 일관되게 개선한다는 증거는 없다.
3. codec latent 내부에서 shared semantic과 target-specific semantic이 자동으로 분리되어
   있다고 볼 근거는 아직 없다. 현재의 output 결과는 그 분리를 증명하지도 반증하지도
   않는다.
4. raw retained data를 중앙에 모으지 않는 **분산 repair**는 아직 구현·검증되지 않았다.

## 5. 이 결과가 제안 방법에 주는 의미

우리의 가설은 다음처럼 더 정확하게 좁혀졌다.

```text
“기존 SCU는 비슷한 데이터까지 항상 함께 망가뜨린다”
```

는 현재 결과로 지지되지 않는다. full SCU의 compensation은 shared semantic을 보호할
가능성이 있다.

대신 더 구체적인 연구 문제는 다음이다.

```text
중앙집중 full SCU가 D_r에서 얻는 retained semantic 보정 역할을,
raw retained data를 중앙에 모으지 않고 남은 client들의 local repair로 어떻게 제공할 것인가?
```

즉 shared semantic guidance 또는 client semantic distribution은 새로운 forgetting
trick을 만들기 위한 장식이 아니라, **분산 repair에 필요한 retained semantic 정보를
어떻게 요약·전달·집계할지**를 해결하기 위한 후보 수단이다. 단, 단일 Gaussian 하나가
충분한지는 현재 증거상 보장할 수 없고, mixture/class-conditional/representation-level
요약을 비교해야 한다.

## 6. 현재 코드와 재현 산출물

현재 실행 흐름은 `src/main.py`에서 시작하며, 다음 구성요소가 마련되어 있다.

| 위치 | 역할 |
| --- | --- |
| `src/models/semantic_codec.py` | MNIST/CIFAR-10 재구성 semantic codec |
| `src/data/data.py` | dataset, split, loader 구성 |
| `src/training/` | FL 학습과 client 0 제외 재학습 |
| `src/unlearning/` | full SCU 및 이후 분산 repair가 들어갈 위치 |
| `src/experiments/federated_deletion.py` | FL 삭제 비교 실행 |
| `src/experiments/support_response.py` | class support와 output gap 분석 |
| `src/evaluation/support_response.py` | `rho` 계산, support 구간 요약, 결과 결합 |

각 run은 config, environment, split 정보, checkpoints, class별 metrics를 별도 output
directory에 보존한다. 이번 핵심 결과의 원본 산출물은 다음에 있다.

```text
outputs/dirichlet_support_original_retrain/
outputs/dirichlet_support_response_original_retrain/
outputs/dirichlet_support_centralized_full_scu/
outputs/dirichlet_support_response_full_scu/
```

## 7. 다음 실험 순서

1. **측정 민감도 보강**: 더 많은 seed, 학습 수렴 확인, retrain 간 noise floor,
   MSE 외 PSNR/MS-SSIM/LPIPS를 추가한다.
2. **support 효과를 더 분명하게 만드는 통제 FL split**: strict target-specific,
   medium, shared-high를 의도적으로 포함한 equal-size split을 만들고 class별
   `origin` 대 `retrain` 변화를 반복 측정한다.
3. **joint forgetting + 분산 repair 구현**: target client 삭제는 encoder와 decoder에
   함께 적용하고, 남은 client들은 raw data를 서버로 보내지 않은 채 local retained data로
   repair한다.
4. **집계 문제 검증**: repair gradient가 forgetting을 되돌릴 수 있으므로 naive FedAvg와
   conflict-aware aggregation을 비교한다.
5. **full method 비교**: joint forgetting only, naive distributed repair,
   conflict-aware distributed repair를 모두 `retrain` 기준으로 평가한다.

이 순서를 따르면 centralized full SCU는 최종 방법이 아니라, 분산 repair가 대체해야 할
retained-data compensation의 비교 기준으로 남는다.
