# FSCU 코드 구조 리팩터링

## 목적

FSCU 실행을 추적하기 어렵게 만들던 전달 전용 함수와 범용 실험 runner를 제거했다.
현재 공식 구현은 public-data FSCU 하나이며, `trainer.py`만 읽어도 서버와 클라이언트의
전체 실행 순서를 확인할 수 있게 한다.

## 현재 실행 흐름

```text
main.py
  -> MPI와 seed 공통 초기화
  -> Trainer.prepare_data
  -> data/data.py의 rank-local data 할당
  -> Trainer.train
  -> train_fscu
  -> 모든 MPI rank가 같은 SPMD 흐름 실행
  -> 새 학습 또는 호환 reference checkpoint load
  -> reference가 없을 때만 Original federated training
  -> reference가 없을 때만 Retrain without target client
  -> target-client joint unlearning
  -> server public-data contrastive compensation
  -> checkpoint 저장
  -> 전체 headline metric 자동 평가
```

`_run_fscu_pipeline`, `run_fscu_public_pipeline`, `_run_server_fscu`,
`_run_client_fscu`는 제거했다. `train_fscu()` 하나가 rank에 따라 소유한 계산만
수행하되 모든 rank가 같은 MPI collective 순서를 직접 따른다.

`--reference-run`을 지정하면 config, seed, full split manifest, checkpoint key/shape/dtype,
저장된 SHA-256을 확인한다. 검증 결과를 모든 rank에 broadcast한 뒤 호환되는 경우에만
Original과 Retrain 단계를 함께 생략한다. source와 checksum은 새 run의
`reference_source.json`에 남긴다.

## 파일 책임

- `src/data/data.py`: 모든 dataset loader, client split, subset, public data, audit probe
- `src/utils/trainer.py`: SCU/FSCU 실행 제어와 MPI 역할
- `src/utils/federated.py`: client-local reconstruction update와 FedAvg
- `src/utils/fscu.py`: target joint unlearning과 server public-data compensation
- `src/utils/loss.py`: public contrastive loss
- `src/utils/fscu_runtime.py`: codec 생성, federated phase, reference 검증용 재사용 함수
- `src/experiments/reconstruction_channel_audit.py`: 저장된 모델의 전체 headline 평가

`src/training/`, `src/unlearning/`, `src/experiments/federated_deletion.py`는 제거했다.

## Config 정리

`load_fscu_config`는 public-data FSCU에 필요한 section과 필드만 한 번 검증한다.
과거 prototype mode별 config class와 긴 validation branch는 사용하지 않는다. FSCU
최적화 함수에는 별도의 config class를 연쇄 생성하지 않고 필요한 값만 담은 dictionary를
전달한다.

## 제거한 미사용 코드

- 과거 PGA, server IB, selective repair prototype
- distributed decoder/joint repair의 과거 실험 구현
- client-specific direction, mask-specificity, remaining-consensus prototype runner
- 동작하지 않던 classification-only `FL` 분기
- 분리되어 있던 MNIST, controlled split, probe data 파일

기존 실험 결과와 연구 판단은 outputs와 문서에 보존한다. 향후 새 방법은 기존 FSCU
분기를 다시 늘리지 않고 명시적인 방법 version으로 구분한다.

## 검증

```text
pytest -q
mpirun --allow-run-as-root -np 11 python -m src.main
  --algorithm FSCU
  --config src/configs/federated_cifar10_vdeepjscc_scu_public_compensation_smoke.json
  --output-root outputs/2026-09-07-26-fscu-refactor-smoke
  --seed 0 --audit-device cpu
```

- Python test 80개 통과
- 11-rank FSCU smoke run 완료
- Original, Retrain, client JU, FSCU checkpoint 생성 확인
- RMSE-255, PSNR, Accuracy, ASR, MIA, BA, Runtime 생성 확인
