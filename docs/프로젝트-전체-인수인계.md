# SCFUL 프로젝트 전체 인수인계

## 이 문서의 목적

이 문서는 이 저장소를 처음 보는 agent 또는 연구자가 현재 연구 목표, 확정된 원칙,
구현 상태, 수행한 실험, 결과 해석, 그리고 바로 다음에 해야 할 일을 한 번에 파악할 수
있도록 만든 최신 요약이다.

세부 실험 문서는 `docs/experiment/`에 보존한다. 이 문서는 그 기록들을 대체하지 않고,
무엇이 유효한 결론이고 무엇이 실패하거나 미검증 상태인지 명확히 구분한다.

작성 기준일: 2026-08-25

## 1. 프로젝트가 풀려는 문제

대상은 일반 분류기가 아니라 재구성 기반 semantic communication codec이다.

```text
이미지 x -> encoder -> power-normalized latent -> wireless channel -> decoder -> 복원 x_hat
```

여러 client가 FL로 encoder와 decoder를 함께 학습한다. 이후 client `u`가 자신의 전체
학습 기여 삭제를 요청한다.

올바른 목표는 target client 입력을 의도적으로 망가뜨리는 것이 아니다.

```text
삭제 후 codec의 동작
    ≈ client u를 처음부터 빼고 다시 FL한 codec의 동작
```

이 문서에서는 이 재학습 model을 `retrain` 또는 **client 제외 재학습 기준 model**이라고
부른다. `oracle`이라는 표현은 사용하지 않는다.

## 2. 반드시 지켜야 하는 연구 원칙

1. 삭제 대상은 sample, class, feature 하나가 아니라 **whole client**다.
2. encoder와 decoder를 함께 다룬다. encoder-only 또는 decoder-only는 ablation일 뿐이다.
3. target reconstruction MSE가 커졌다는 사실만으로 unlearning 성공을 주장하지 않는다.
4. 주 성공 지표는 `retrain`과의 functional gap이다.
5. 최종 제안 방법의 server는 remaining client의 raw data를 받으면 안 된다.
6. remaining client의 local repair는 자기 local retained data에서만 수행한다.
7. original model distillation을 쓴다면 remaining client data에서만 쓴다.
8. AWGN, Rayleigh, SNR 변화 등 물리 채널을 연구 범위에서 제거하지 않는다.
9. `forget-only`는 유효한 SCU 또는 제안 방법 baseline으로 더 이상 사용하지 않는다.

## 3. 용어

| 표기 | 뜻 | 주의점 |
| --- | --- | --- |
| `origin` | 모든 client로 FL한 원본 global codec | 삭제 전 model |
| `retrain` | target client 없이 처음부터 다시 FL한 기준 codec | 유일한 최종 비교 기준 |
| `G-u` | 마지막 원본 FL round에서 target을 제외한 local model들의 평균 | `retrain`이 아님. remaining-client reference일 뿐 |
| `U` | target client의 정상 마지막-round local model | target이 삭제 전 가진 local 정보 |
| `G-un` | target client가 자기 data로 local unlearning한 model | 삭제 신호지만 shared utility도 손상했을 수 있음 |
| `D_pub` | client split 전에 따로 떼어 둔 공개 calibration data | server가 raw retained data 대신 사용할 수 있다는 가정 |
| output gap | 어떤 model reconstruction과 `retrain` reconstruction의 평균 제곱 차이 | 작을수록 retrain 동작에 가까움 |
| support / deletion fraction | 한 class에서 target client가 차지한 data 비율 | 높을수록 삭제 뒤 남는 class support가 적음 |

## 4. 현재 프레임워크의 철학

한 문장으로 정리하면 다음과 같다.

> target client의 고유 기여만 약화하고, remaining clients가 지지하는 shared semantic은 raw data 중앙화 없이 복구한다.

현재 의도한 파이프라인은 다음과 같다.

```text
1. 모든 client가 정상 FL을 수행한다.
2. target client u는 정상 local model U를 server에 업로드한다.
3. target client u는 자기 data로 local unlearning을 수행해 G-un을 server에 보낸다.
4. server는 target을 제외한 local model을 평균내 G-u를 만든다.
5. server는 D_pub에서 U, G-u, G-un을 비교해
   - 삭제해야 할 target-specific 정보는 보존적으로 약화하고
   - 손상된 shared semantic은 G-u 방향으로 복구한다.
6. target을 제외한 clients가 각자 local retained data로 distributed repair한다.
7. server는 repair update가 삭제 효과를 되돌리지 않게 conflict-aware하게 집계한다.
8. 최종 model을 retrain과 비교한다.
```

여기서 역할 분리는 중요하다.

```text
G-un: target이 지우려 한 정보의 신호
G-u : remaining clients가 유지하는 정보의 reference
U   : target이 삭제 전 보유했던 정보의 reference
```

`G-un` 전체를 따라가면 target local unlearning의 utility 손상까지 복사하게 된다.
따라서 `G-un`은 final teacher가 아니라, 선택적으로 다뤄야 하는 deletion signal이다.

## 6. 실험 진행 과정과 결론

### 6.1 통제된 MNIST/CIFAR centralized behavior 실험

목적은 “정상적인 client 삭제 뒤 model이 무엇을 보여야 하는가”를 확인하는 것이었다.

비교 model:

```text
origin
retrain
SCU-style forget-only
SCU-style self-sharing / centralized full SCU
```

핵심 결론:

- target client data를 뺀 `retrain`도 target과 유사한 입력을 복원할 수 있다.
- 따라서 target image reconstruction MSE를 강제로 높이는 것은 올바른 삭제 기준이 아니다.
- `forget-only`는 target뿐 아니라 retained sample도 붕괴시킨다.
- retained data를 같이 쓰는 self-sharing/full SCU는 utility 붕괴를 줄일 수 있다.
- single Gaussian 하나로 client semantic distribution을 표현하기에는 multimodal class
  구조와 posterior dependence가 남는다.

관련 기록:

- `docs/experiment/08-13-02-통제된-non-iid-파일럿-분석.md`
- `docs/experiment/08-16-02-cifar10-200epoch-분석.md`

### 6.2 20 epoch가 부족하다는 확인과 200 epoch 기준 채택

CIFAR-10 centralized 비교에서 20 epoch 이후에도 reconstruction loss가 계속 크게
감소했다. 그래서 이후 CIFAR-10 주요 비교는 200 epoch 또는 FL 200 rounds를 기준으로
잡았다.

200 epoch에서도 완전 수렴이라고 단정할 수는 없지만, 20 epoch보다 훨씬 공정한
비교 조건이다.

### 6.3 FedOSD형 pathological split의 centralized full SCU

설정:

- 10 clients, client당 2 classes
- client 0과 client 1이 label 0, 1을 함께 보유하는 strong shared 조건
- target은 client 0
- server는 full SCU comparator에서 retained raw data를 직접 사용

seed 0 결과:

| model | 전체 reconstruction MSE | retrain과의 output gap |
| --- | ---: | ---: |
| origin | 0.015428 | 0.000260 |
| retrain | 0.015418 | 0.000000 |
| centralized full SCU | 0.014737 | 0.000738 |

결론:

- full SCU는 forget-only처럼 codec 전체를 붕괴시키지 않았다.
- 그러나 이 조건에서 origin보다 retrain에 더 가까워졌다고 말할 수는 없다.
- 따라서 “기존 SCU는 유사 semantic을 항상 함께 망가뜨린다”는 가설은 지지되지 않는다.
- 더 정확한 연구 질문은 중앙의 retained-data compensation 역할을 distributed repair로
  어떻게 대체할 것인가다.

관련 기록: `docs/experiment/08-17-04-중앙집중-full-scu-seed0-결과.md`

### 6.4 Dirichlet alpha 0.1 support 감소 분석

목적은 target client 삭제가 특정 class의 support를 크게 줄였을 때 origin과 retrain의
behavior 차이가 커지는지 보는 것이었다.

조건:

- 10 clients
- 모든 client의 data 수는 같음
- class 비율만 Dirichlet alpha 0.1로 불균형
- origin/retrain을 200 rounds로 5 seeds 실행

결과:

| support 구간 | 관측 수 | origin의 평균 output gap |
| --- | ---: | ---: |
| shared-high | 2 | 0.000234 |
| medium | 6 | 0.000246 |
| low-support | 2 | 0.000275 |

삭제 비율과 gap의 Pearson 상관은 0.164, 순위 상관은 0.067이었다.

결론:

- 삭제 후 class support 차이는 실제로 크게 생긴다.
- 하지만 현재 5-seed 조건에서는 support 감소가 output gap을 확실히 키운다는 단조
  관계를 아직 확인하지 못했다.
- shared와 target-specific은 고정 이분법보다 남은 support의 연속적 정도로 다뤄야 한다.

관련 기록:

- `docs/experiment/08-18-01-dirichlet-support-반응-분석.md`
- `docs/experiment/08-18-02-dirichlet-full-scu-support-분석.md`
- `docs/experiment/08-18-03-프로젝트-진행-흐름과-현재-결론.md`

### 6.5 첫 공개 데이터 3-model server 방법: direct matching 실패

초기 구현은 다음 방식이었다.

```text
G-u에서 server candidate를 시작
candidate와 U의 representation similarity는 낮춤
candidate와 G-un의 전체 representation similarity는 높임
G-u anchor를 추가
```

CIFAR-10 Dirichlet alpha 0.1, 10 clients, 200 rounds, seed 0 결과:

| model | output gap |
| --- | ---: |
| `G-u` | 0.000228 |
| `G-un` PGA | 0.058370 |
| direct server matching 직후 | 0.011942 |
| 이후 naive distributed repair | 0.000264 |
| 이후 conflict-aware repair | 0.000533 |

결론:

- `G-un`은 target deletion signal이지만 utility 손상이 매우 크다.
- `G-un` 전체를 teacher처럼 따라가면 그 손상도 server model에 복사된다.
- 현재 전체 parameter-space conflict projection도 naive repair보다 나빴다.

관련 기록: `docs/experiment/08-19-01-공개데이터-pga-ib-분산repair-시드0-결과.md`

### 6.6 `G-un` 시작 선택적 server repair

direct matching 문제를 피하기 위해 다음 방식으로 고쳤다.

```text
mask 선택: D_pub에서 U와 G-u 차이가 큰 global top-k latent coordinate
server 시작점: G-un
선택된 k개 coordinate: G-un 쪽을 보호
나머지 coordinate: G-u 쪽으로 복구
출력 수준: sample별 U-G-u 차이가 클수록 G-un 보호 비중을 높임
그 뒤: remaining 9 clients의 distributed repair
```

동일한 CIFAR-10 Dirichlet alpha 0.1, 200-round, seed 0 결과:

| model | reconstruction MSE | output gap |
| --- | ---: | ---: |
| origin | 0.013516 | 0.000229 |
| retrain | 0.013516 | 0.000000 |
| `G-un` PGA | 0.072121 | 0.058370 |
| 선택적 server repair | 0.029567 | 0.015894 |
| 선택적 server repair + naive repair | 0.013380 | 0.000245 |
| 선택적 server repair + conflict-aware repair | 0.013560 | 0.000316 |

결론:

- 선택적 단계는 `G-un`의 큰 손상을 일부 복구했다.
- 그러나 server 단계만으로 retrain과 충분히 가까워지지 못했다.
- naive distributed repair 뒤 utility와 output gap은 상당히 회복됐지만, single seed의
  작은 차이만으로 deletion 품질이나 방법 우위를 주장할 수 없다.
- 현재 conflict-aware aggregation은 선택적 철학과 맞지 않는 전체 parameter 방향을
  사용하므로 재설계가 필요하다.

관련 기록: `docs/experiment/08-19-02-선택적-server-repair-시드0-결과.md`

### 6.7 최신 strict target-specific mask 검증: 현재 top-k 규칙은 실패

이 실험은 가장 최근에 추가했다. 목적은 현재 선택 mask가 실제 target-specific semantic을
찾는지, 정답이 명확한 조건에서 검증하는 것이다.

strict split:

```text
공개 calibration data를 class당 100장씩 train에서 먼저 분리
client 0: class 0의 남은 4,900장을 모두 보유
client 1~9: class 1~9를 각각 하나씩 보유
target client: client 0
```

따라서 class 0은 data allocation 기준으로 100% target-specific이고, class 1~9는
target client가 보지 않은 retained-only class다.

mask는 `D_pub`에서만 고르고, selection에 쓰지 않은 CIFAR-10 test 10,000장에서 다음
score로 평가했다.

```text
mask score(x)
= 선택된 latent 차원에서의 평균 |normalize(mu_U(x)) - normalize(mu_G-u(x))|
```

class 0을 positive, class 1~9를 negative로 하여 AUC를 계산하고, 같은 크기의 random
mask 200개와 비교했다.

seed 0 결과:

| 지표 | 값 |
| --- | ---: |
| 선택 mask 크기 | 16 / 64 차원 |
| selected-mask AUC | 0.5173 |
| 전체 latent score AUC | 0.6251 |
| random-mask AUC 평균 | 0.6026 |
| random-mask AUC 최대 | 0.7452 |
| random mask가 selected AUC 이상일 permutation 비율 | 0.9154 |

class 0의 selected score는 0.03280이었고, 다른 class도 0.0317~0.0339 범위였다.
또한 선택된 16개 차원은 class 0뿐 아니라 모든 class에서 `U`-`G-u` 차이의 약
55~76%를 차지했다.

현재 결론:

> `U`와 `G-u`의 공개 데이터 전체 평균 차이가 큰 latent coordinate를 global top-k로
> 고르는 현재 규칙은, 가장 쉬운 strict target-specific 조건에서도 class 0을 구분하지
> 못했다.

이는 중요한 반증 결과다. 이 규칙은 target-specific semantic보다 local model 간의
전역적인 client drift를 선택하는 것으로 보인다. 따라서 이 top-k mask를 제안 방법의
핵심 근거로 사용하면 안 된다.

완료 run:

```text
config:  src/configs/federated_cifar10_target_exclusive_mask_specificity.json
output:  outputs/target_exclusive_mask_specificity/20260825T054614Z_seed-0/
```

상세 기록: `docs/experiment/08-25-01-strict-target-specific-mask-검증.md`

seed 1~4 multi-seed 실행은 사용자의 요청으로 시작 직후 중단했다. 해당 미완료
directory가 있더라도 결과로 사용하면 안 된다.

## 7. 현재 시점의 상태 판정

| 항목 | 상태 | 판단 |
| --- | --- | --- |
| retrain 기준 평가 | 완료 | 모든 주요 FL run에서 적용 |
| AWGN codec과 10-client FL | 완료 | CIFAR-10 200-round 실행 가능 |
| raw retained data 비중앙화 repair | 구현됨 | remaining client가 local repair 후 update만 전송 |
| centralized full SCU comparator | 완료 | retained-data compensation 필요성 진단용 |
| PGA `G-un` 생성 | 구현됨 | 최종 forgetting 규칙으로 확정되지 않음 |
| `G-un` 전체 direct matching | 반증됨 | utility 손상을 복사함 |
| global top-k `U`-`G-u` latent mask | 반증됨 | strict class-0 조건에서 specificity 실패 |
| naive distributed repair utility 회복 | 관측됨 | deletion 보존은 아직 미검증 |
| conflict-aware aggregation | 구현은 됨, 효과는 미확인 | 현재 방식은 naive보다 나쁨 |
| membership/privacy 평가 | 미구현 | 삭제 성공을 주장할 수 없는 핵심 공백 |
| latent client-specific 정보 식별 | 미해결 | 현재 연구의 바로 다음 핵심 문제 |

## 8. 다음에 해야 할 일

현재는 mask 비율, protection weight, multi-seed ablation을 바로 늘릴 단계가 아니다.
그 전에 top-k mask 기준 자체를 바꿔야 한다.

우선순위는 다음과 같다.

1. **실패 원인 분석**
   - `U`와 `G-u`의 차이가 모든 class에서 비슷하게 커지는 이유를 확인한다.
   - global latent coordinate 평균 대신 input-dependent score, class-conditional prototype,
     또는 subspace를 고려한다.
   - `G-un`이 주는 deletion signal까지 포함하되, 전체 `G-un`을 teacher로 쓰지는 않는다.

2. **새 specificity 기준의 strict 재검증**
   - 같은 target-exclusive split에서 class 0 대 class 1~9 AUC를 다시 측정한다.
   - random mask보다 높은 AUC를 보이기 전에는 mixed shared/target-dominant split으로
     확장하지 않는다.

3. **mixed support split으로 확장**
   - strict 검증을 통과한 뒤 client 0 안에 target-dominant class와 shared class를 함께
     넣는다.
   - target-dominant class, shared class, retained-only class에 대해 mask score와 retrain
     functional gap을 따로 평가한다.

4. **삭제 품질 평가 추가**
   - target training member와 held-out target probe를 분리한다.
   - membership inference 또는 latent client-identity leakage를 추가한다.
   - utility가 회복된 model이 target membership도 실제로 제거했는지 확인한다.

5. **representation-aware conflict aggregation 재설계**
   - 전체 parameter update 하나를 forgetting direction으로 쓰지 않는다.
   - 검증된 target-sensitive representation 또는 update 성분만 보호 대상으로 삼는다.

## 9. 새 agent가 작업할 때의 주의점

- `G-u`를 `retrain`이라고 부르지 않는다.
- target input을 잘 복원한다고 해서 deletion 실패라고 판단하지 않는다.
- `forget-only`를 다시 주 baseline으로 실행하지 않는다.
- centralized full SCU의 retained raw data 사용은 comparator에만 허용된다.
- final distributed method에서는 server로 raw remaining data를 보내면 안 된다.
- `G-un`은 전체 semantic teacher가 아니라 deletion signal이다.
- 현재 global top-k mask는 strict 검증에서 실패했으므로, 효과가 있다고 전제하면 안 된다.
- 하나의 seed, 작은 output gap 차이만으로 방법 우위를 주장하지 않는다.
- 새 실험 문서는 `docs/experiment/MM-DD-Index-간단한제목.md` 형식으로 한국어로 만든다.
